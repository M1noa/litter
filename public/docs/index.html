api docs

base url: https://litter.minoa.cat

standard upload

POST /api/upload

upload small files (up to 100mb) directly in a single request.

parameters

name type description
file file the file data (multipart/form-data)

example

curl -F "file=@photo.jpg" https://litter.minoa.cat/api/upload

response

{
  "url": "https://litter.minoa.cat/files/34873485/photo.jpg",
  "deleteSecret": "0a1b2c3d..."
}

large file upload (chunked)

recommended for files > 100mb. supports files up to 80gb. this is a 3-step process to ensure reliability.

1 initialize session

POST /api/upload/chunk/init 
// body (json)
{
  "filename": "movie.mp4",
  "fileSize": 524288000,
  "totalChunks": 25, // optional, will be calculated automatically if omitted
  "mimeType": "video/mp4", // optional
  "fileHash": "..." // optional sha-256 for deduplication
}

// returns
{
  "uploadId": "uuid-string",
  "partsCount": 25,
  "chunkSize": 20971520,
  "expiresAt": 1718900000000
}

2 upload parts

POST /api/upload/chunk/:id/:partnum

upload individual parts (chunks). partnum is 0-indexed. overwriting parts is allowed for retries. 

// url example
POST /api/upload/chunk/uuid-string/0

// form data
file: [binary data]

// returns
{ "success": true, "progress": 4 }

3 finalize

POST /api/upload/chunk/:id/complete

server reassembles all chunks and moves the file to permanent storage.

// returns
{
  "url": "https://litter.minoa.cat/files/5829384/movie.mp4",
  "deleteSecret": "0a1b2c3d..."
}

upload queue & concurrency

chunked upload init and part uploads are also subject to traffic management. if the server is at capacity, these endpoints may return:

codemeaning
429per-ip upload limit reached (5 concurrent uploads per ip)
503server at capacity — queue full
408queue timeout (60s waiting for upload slot)

file deletion

DELETE /files/:id/:filename

delete a file using the secret returned from upload. the secret can be provided via: 

// header (recommended - not logged)
DELETE /files/abc123/file.jpg
X-Delete-Secret: 0a1b2c...

// query param (convenient but may appear in logs)
DELETE /files/abc123/file.jpg?secret=0a1b2c...

// json body
DELETE /files/abc123/file.jpg
{ "secret": "0a1b2c..." }

response

{ "success": true, "message": "File has been successfully deleted." }

traffic management

when the server is under load, uploads and downloads are managed through a traffic queue system. requests that exceed per-ip limits or server capacity are queued until a slot is available. authenticated requests bypass both queue and throttle entirely.

concurrency limits

limit value env variable
max concurrent uploads 30 TRAFFIC_MAX_CONCURRENT_UPLOADS
max chunk sessions 20 —
max chunk part uploads 30 —
max concurrent downloads 80 —

per-ip limits

type limit error code when exceeded
concurrent uploads per ip 5 429
concurrent downloads per ip 10 429

throttling

when concurrent requests exceed the "on" threshold, speed is limited per ip. throttling turns off once concurrent requests drop below the "off" threshold (hysteresis to prevent flapping).

type throttle on throttle off speed limit per ip
uploads 15 concurrent 12 concurrent 3 mbps
downloads 55 concurrent 45 concurrent 3.5 mbps

queue behavior

status code meaning
202 request queued — browser clients receive queue json with position and estimated wait
408 queue timeout — request waited 60s without getting a slot
429 per-ip limit reached (5 uploads / 10 downloads per ip)
503 server at capacity — queue is full, cannot accept more requests

queue timeout is 60 seconds. authenticated requests (with valid api token) bypass both queue and throttle entirely.
